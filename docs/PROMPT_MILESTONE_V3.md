## 一、总体原则

1. **Git 版本管控（需求 1）**：本版本起所有升级走 Git 管控：
   - 采用语义化版本号：主版本.次版本.修订（如 1.0.0 → 1.1.0 → 1.0.1）；
   - 每次升级必须：更新 CHANGELOG.md → 打 Git tag（如 v1.1.0）→ 推送 GitHub；
   - Android versionName 与 tag 一致、versionCode 每次升级递增；Web 构建产物携带版本号；
   - 阿里云部署记录对应 commit/tag。
2. 安全红线沿用：验证码/密码/令牌/密钥不落明文、不写审计日志与日志上传；HTTPS 为公网唯一通道
   （保留局域网 HTTP 回退）；家长身份验证必须云端账号密码。
3. 离线语义沿用：已下发内容本地照常执行，离线仅停止同步，恢复后增量同步 + 补报。
4. 涉及用户决策项（见“决策点”）先出清单/方案给产品负责人确认，确认后再实施。

### 3. 新旧账号登录提醒
- 儿童端/家长端在检测到本地存在旧账号残留（家长端：旧邮箱/JWT/服务器地址；儿童端：旧绑定信息/
  本地业务数据）时，新账号登录/绑定必须弹出提醒：“检测到旧账号数据，继续将清除旧数据并绑定新账号”，
  用户确认后才继续。
- 提醒文案明确列出将清除的内容（需求 4 范围）。

### 4. 解绑重绑后旧数据清除干净
- 解除绑定（或换绑）后，旧账号相关数据全部清除：公告、策略、分类、使用记录/报告缓存、
  家长端凭据（JWT/邮箱）、中继配置、本地缓存；清除动作需家长账号密码验证（沿用现状）。
- 是否连 device_id 一并重置：见决策点 D2（默认建议保留 device_id，避免重复建设备）。
- 提供清除后的干净状态验证（数据库/本地文件/UI 三处核对）。

### 5. 修复“上滑结束小趴菜后管控失效”真机 Bug
- 现象：限额到期后被管控 App 被拦截；用户上滑结束小趴菜进程后，被管控 App 恢复可用。
- 目标：加固守护自愈——前台服务防杀提示与 START_STICKY、无障碍服务断开自愈、被手动结束后
  的恢复机制（如 JobScheduler/WorkManager/通知引导一键重启）、OPPO 等厂商保活引导（电池优化/自启动，
  已有权限引导页扩展）。
- 能力边界如实说明：Android 第三方应用无法绝对阻止用户手动结束进程；验收报告须注明该边界与
  缓解措施（如被杀后尽快恢复并通知家长）。

### 6. 删除初始化/登录时的运行命令提示
- 移除 APP 初始化与登录流程中的“运行命令/ADB 命令/调试指令”等开发提示（核对具体位置后全部删除，
  保留普通用户文案）。测试用途的 ADB 授权入口改为隐藏调试通道，不出现于普通用户界面。

### 7. 关于页修正（含需求 12 统一）
- 关于页年份不再写死（当前 2024 不正确），改为动态年份；
- 版本号跟随 Git：versionName=Git tag、versionCode 递增，构建时自动注入；
- 关于页展示官网域名 xpc.winann.com（可点击打开 https://xpc.winann.com）；
- 家长端与儿童端“关于”使用同一组件，内容完全一致。

### 8. 删除家长端 ADB 快速指南
- 家长端“电脑 ADB 一条命令 · 约 30 秒 · 快速授权指南”卡片/入口删除。

### 9. 隐藏家长端分类限额
- Android 家长端策略配置中的“分类限额”入口隐藏（本期不启用）；Web 端维持“暂不可用”标注；
  后端逻辑保留不删。

### 10. 家长端策略与公告和 Web 双向同步
- Android 家长端策略管理、公告管理具备查看与编辑能力，与服务端（Web 同源）双向同步：
  任意一端修改，全端一致；服务端为权威，离线本地缓存可看，恢复后即时同步。
- 同步冲突规则：以服务端最新版本为准；新账号绑定全量覆盖。

### 11. 报告页与 Web 同步
- APP 报告页数据口径与 Web 完全一致（周期报告、分类统计、原始累计+重置偏移、调整后已用）；
  在线实时拉取，离线展示本地缓存并标注“离线数据”，恢复后自动刷新。

### 12. 关于统一（并入需求 7）

### 13. Web 云端中继设置开放范围（决策点 D3）

## 三、决策点（已确认）

- D1（需求 2）：场景清单已逐项确认（见附录“D1 决策汇总”）。
- D2（需求 4）：**解绑后全清，device_id 一并清除**（重绑生成全新设备身份）。
- D3（需求 13）：**隐藏** Web 云端中继设置（普通家长不可见；服务端自动中继不受影响）。
- D4（需求 6/8）：**全部删除** ADB/运行命令/调试提示（初始化、登录、家长端快速指南等普通用户界面一律移除）。
- D5（需求 10）：**保证双向及以后多向一致**（策略/公告以服务端为权威，任意端修改全端同步，冲突以服务端最新版本为准并做版本/时间戳校验）。
- D6（需求 14）：日志上传按推荐执行——自动定期 + 手动按钮；Web 端保留最近 7 天。

## D1 决策汇总（已确认）

### A. 策略下发
- A1 首次绑定默认策略：**不调整**（120 分钟 / full_lock）。
- A2 多端冲突：**采用建议**——服务端版本/时间戳校验，以服务端最新版本为准。
- A5 账号级策略模板（一键套用全部设备）：**本期不做**。
- A12 解绑清理：**采用建议**——解绑即删除设备行 + 策略 + 公告送达记录等全部关联数据（配合 D2 全清）。

### B. 家长公告
- B2 发布紧急公告：**采用建议**——服务端推送后 60 秒未收到 displayed 回执则对在线设备补偿重推。
- B3 编辑已发布公告：**维持不变**（已发布不可编辑，需先撤回）。
- B5 删除公告：**采用建议**——新增“清除本地公告”指令，删除时通知客户端清除本地记录（多端一致）。
- B6 离线发布：**采用建议**——紧急且未确认的公告重连时必补推（不限于 1 小时窗口）。
- B8 去重：**采用建议修复**——紧急未确认公告在重连补推时必须重新全屏（upsert=unchanged 不再跳过紧急未确认）。
- B10 推送后未处理：**采用建议**——与 B2 同（60 秒补偿重推）。
- B11 多设备广播：**采用建议修复**——公告只推发布者账号下的设备（账号隔离）。
- B13 公告归属：**采用建议**——公告归账号，同账号所有设备可见。
- B14 定向公告：**先不动**（UI 暂不开放，后端 TargetDeviceId 能力保留）。
