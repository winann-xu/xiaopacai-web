# ADR 0008：K3 限速自锁闭环修复（TASK-PRELAUNCH-FIX-RATELIMIT）

- 日期：2026-08-15
- 状态：已接受
- 相关：ADR 0007（error_code 协议表）、SECURITY_BASELINE.md SEC-K3（p2p-handshake:ip / p2p-paircode，10 次失败/5 分钟）
- 任务：Codex 122 信（阿里云公网实测复现），用户红线约束下自行裁决实施

## 背景（122 信，生产/公网实测）

K3 IP 限速拒绝分支（`P2pMessageHandler.HandleHandshake`）返回 `handshake_rejected` 但未填 `ErrorCode`，线上回执 `error_code:""`。儿童端 `isDeterministicRejectionCode("")==false` → 按临时失败处理 → 1s 短退避重连。闭环：

1. 10 次失败打满 K3 → IP 封禁 5 分钟；
2. 封禁期内每次 1s 重试都收到 `error_code:""` 的拒绝（无法识别为限速）；
3. 窗口过期后，1s 频率的重试在约 60 秒内重新打满 10 次失败 → 再次封禁；
4. 无限循环：IP 长期处于「封禁 5 分钟 + 10 秒重打满」的交替中，实测 16:48–17:02+ 连续 blocked；服务重启清空桶后 01:01 复现同样锁死。

（注：封禁分支本身 `return` 早退不调用 `RecordFailure`——封禁期内不计次，窗口不会因被拦请求续期；真正的自锁机制是「窗口过期后 1s 重试快速重新打满」。）

## 决策

### 1. 服务端：限速拒绝补显式错误码 `ip_rate_limited`

- 封禁分支 `HandshakeResponse.ErrorCode = "ip_rate_limited"`，其余行为不变（审计照记 R9.1、不计失败次数）。
- `HandshakeResponse.ErrorCode` 文档补充该码语义。

### 2. 服务端：封禁期内不重复计次（确认现状，不改代码）

- 封禁分支早退、不调用 `RecordFailure`——封禁窗口从「第 10 次失败」起算固定 5 分钟，不因被拦请求续期；冷却后自动放行（自愈）。
- 与「继续计数」方案对比：两者封禁时长对攻击者一致（被封禁期间什么都做不了），但不计次保证窗口过期必然放行，且避免审计/拒绝循环放大。安全不减、可用性恢复。

### 3. 儿童端：`ip_rate_limited` 独立于确定性拒绝——长指数退避 + 自动重连

- `ip_rate_limited` 语义：临时性失败，**允许并保持自动重连**，但退避参数独立：
  - 首退 60s，指数翻倍，**上限 10 分钟**（服务端窗口 5 分钟，封顶后必然落在窗口之外 → 闭环自愈）；
  - 成功连接后 `rateLimitBackoffStep` 归零。
- 拒绝发生时：清配对码（含加密持久化副本，旧码多为失败根源；D3 已保证已配对设备重连免码）、**保留连接配置**、写入 `handshakeRejection` 状态流供 UI 提示、关闭本次 socket，调度长退避重连。
- **不**按确定性拒绝停止重连（冷却后应自动恢复，无需用户干预）。
- 配对管理器（PairingManager）对该码不落 `PairingState.ERROR` 终态；UI 显示警示色「⏳ 尝试次数过多，请稍后自动重试」。

### 4. 儿童端：空 `error_code` 防御性映射为 `ip_rate_limited`

- 旧服务端唯一不带 error_code 的拒绝分支是 K3 限速（其余分支均已显式赋值），空白码必然来自旧版限速分支 → 客户端按限速处理（长退避而非 1s 续期）。
- 新服务端补齐显式码后该映射仅对存量旧服务端生效；不影响其他路径（其他分支均带码）。

### 5. 退出退避的路径

- 成功握手（CONNECTED）→ 退避步数归零，进入正常心跳/收发；
- 确定性拒绝（unpaired 等）→ 停止重连回配对界面（ADR 0007 语义不变）；
- 用户主动断开/重新扫码（`disconnect()` → DISCONNECTED）→ 待触发退避任务因状态守卫不再执行。

## 后果

- 正：限速闭环自愈——儿童端在封禁期不再 1s 轰炸（60s 起跳、10 分钟封顶），窗口过期后单次重连即成功；审计日志风暴消失；`ip_rate_limited` 明确可测可判定。
- 负：被限速的儿童端恢复时间最长约「窗口 5 分钟 + 退避 10 分钟」（首次退避 60s 落在窗口内时）；属可接受的安全-可用性平衡。
- 安全不变：K3 封禁时长不变（固定 5 分钟自第 10 次失败），爆破计数在服务端仍生效；`ip_rate_limited` 不削弱任何红线。

## 验收要点（Codex 执行）

1. 模拟器打满 K3 后：回执 `error_code=ip_rate_limited`；客户端日志出现「限速退避：将在 60000ms/120000ms…」且无 1s 重连；
2. 窗口冷却后自动重连成功，UI 恢复「✅ 已连接到家长端」，退避步数归零；
3. 被限速期间 UI 显示「⏳ 尝试次数过多，请稍后自动重试」（警示色），非「❌ 配对失败」终态；
4. 确定性拒绝（unpaired/revoked/指纹不匹配/无效码）行为与 118 信验收一致，无回归；
5. 阿里云生产部署后复测闭环：打满 → 等待 → 自愈，全程无人工干预。
