# 小趴菜 App 自动更新 ｜ 标准提示词 V1.0（待产品负责人审核）

任务 ID：[TASK-APP-UPDATE-V1]
范围：Web + Android（本期）；Windows 家长端本期仅预留接口文档，不改实现（除明确说明外）。

## 一、任务目标
为小趴菜建立完整的 App 自动更新闭环：
- 服务端（Web admin）增加「推送更新」按钮，点击后已安装客户端收到更新通知，用户同意更新或在后台预下载后自动更新；
- Android 客户端「家长端 → 关于」新增「更新软件」按钮，指向 xpc.winann.com 下载中心；
- 所有程序更新不得影响既有用户的登录数据与运行数据（登录态、配对绑定、策略、公告、使用记录、报告缓存、本地加密库与密钥）；
- 调研成熟 App 的更新设计（强制/可选更新、更新说明、ABI 匹配、完整性校验、WiFi 预下载、降级防护等），符合本场景的一并纳入。

## 二、不可违背的原则（产品负责人定夺）
1. **数据保留是硬红线**：升级必须保留 SharedPreferences（JWT/邮箱/角色/服务器地址）、设备绑定与配对、策略/公告/分类/使用记录/报告缓存、KeyStore 密钥与 P2P 客户端证书、加密数据库文件。任何升级路径（手动/推送/后台）都不得触发本地清库；`MY_PACKAGE_REPLACED` 现有行为仅做权限自检，需复核不清理数据。
2. **安全红线**：更新清单与 APK 下载仅 HTTPS；安装前必须校验 SHA-256；禁止降级（versionCode 单调递增 + 可选已装证书比对，防止替换包/中间人）；下载中心沿用现有白名单中间件；admin 发布/推送动作写审计。
3. **能力边界如实说明**：Android 非系统应用无法在用户无确认下真正静默安装（平台硬限制）。「后台自动更新」实现为「WiFi 下自动预下载 + 安装时一次系统确认（引导未知来源）」；验收文档须注明该边界。
4. **强制更新不可跳过**：低于 minVersionCode 的客户端必须更新才能继续使用对应功能（家长端进入前拦截；儿童端不因此中断守护）；可选更新可「以后再说」「跳过此版本」。
5. **儿童端守护不被更新流程打断**：下载/安装/提示过程不得解除超时拦截、无障碍或前台守护；更新完成进程重启后守护自动恢复（现有 START_STICKY/自启机制沿用）。
6. **频控与去重**：更新检查限频（防启动风暴）；可选更新提示按「版本 + 每日一次」去重，强制更新每次进入按规则提示；推送触达不重复轰炸。
7. **权限收敛**：只有 admin 能发布/推送更新；普通家长端只能触发本设备检查。更新清单接口不泄露敏感数据。

## 三、功能需求
### A. 服务端（xiaopacai-web/server）
A1 更新清单表 `app_updates`（或等价配置）：
- id / platform（android/windows）/ version_name / version_code / min_version_code（强制阈值）/
  abi_urls（arm64-v8a、armeabi-v7a、x86_64 分别的下载路径）/ abi_sha256（各 ABI 的 SHA-256）/
  size_bytes / changelog（更新说明）/ status（draft/published）/ published_at / created_by / created_at。
- 每个 version_code 至少一个 ABI 可用；无当前 ABI 包时客户端明确提示「暂不支持本设备」。

A2 公开检查接口：
- `GET /api/update/check?platform=android&abi=arm64-v8a&versionCode=10106`：
  返回 `{ hasUpdate, latestVersionCode, latestVersionName, minVersionCode, force, url, sha256, sizeBytes, changelog, publishedAt }`；
  `force = minVersionCode > 当前 versionCode`；无更新或参数非法返回明确无更新/错误。
- 公开接口限频（IP 级，沿用现有限速设施）；响应仅含更新所需字段，不含敏感配置。

A3 admin 发布/推送：
- `POST /api/admin/updates/{id}/publish`：draft → published，记录 published_at，写审计；
  向在线设备 P2P 推送 `update_available`（复用公告/策略推送通道，含 updateId/versionCode 摘要），
  离线设备由启动/重连检查补上。
- 推送范围默认「全部在线设备 + 离线补检」，定向推送（按账号/设备）本期预留能力（见 D2）。

A4 下载中心：
- 沿用 `/downloads/*` 白名单；APK 文件名带版本+ABI（如 `XiaopacaiParent-1.1.6-arm64-v8a.apk`）；
- 上传时由服务端计算 SHA-256 入库（上传工具或 admin 页面上传均可，推荐 admin 页面上传）。

### B. Web 前端（xiaopacai-web/web）
B1 admin 更新管理页：
- 上传 APK（按 ABI）、填写版本名/版本号/强制阈值/更新说明；上传后展示自动计算的 SHA-256 与大小；
- 列表/详情/草稿/发布；「发布并推送」按钮（含二次确认与审计提示）；
- 历史版本列表（含发布时间、推送范围、强制标记）。
B2 公共下载页 `DownloadPage` 展示最新版本、更新说明与各 ABI 下载入口（与现有下载中心合并呈现）。

### C. Android（xiaopacai/android）
C1 更新检查触发点：
- 应用启动后（家长端进入前）静默检查；
- 服务端 P2P `update_available` 推送触发（在线设备即时提示）；
- 家长端「关于 → 更新软件」手动检查；
- 支持"检查更新"按钮在无更新时提示「已是最新版本」。

C2 版本判定与 UI：
- 更新对话框：新版本号、更新说明（changelog）、包大小、强制/可选标签；
- 可选更新：「立即更新」「以后再说」「跳过此版本」；强制更新：仅「立即更新」（不可关闭，儿童端不阻塞守护但提示家长处理）；
- 无更新 / 已是最新：不弹窗，仅手动检查时提示。

C3 下载与安装：
- 下载到应用私有目录；显示进度（对话框内进度条 + 系统通知进度）；
- 下载完成后校验 SHA-256，失败拒绝安装并提示重试/重新下载；
- 安装走 `PackageInstaller`（session）或 `FileProvider + ACTION_VIEW`（按设备兼容性选择主备）；
- 申请/引导 `REQUEST_INSTALL_PACKAGES`（未知来源）权限；拒绝时给出明确引导文案；
- 安装完成/失败结果回调：成功提示、失败可重试；升级后进程重启，守护自启恢复。

C4 通知：
- 新增更新通知通道（与公告通道并列）；推送触达生成通知，点击进入更新对话框；
- 下载中/完成/失败均有通知反馈。

C5 家长端「关于」页：
- 在统一 About 组件或家长端设置-关于内新增「更新软件」按钮：点击先走 C2 检查流程，
  无更新或检查失败时兜底打开 https://xpc.winann.com（下载中心）。

C6 后台预下载（自动更新）：
- 设置项「WiFi 下自动下载更新」（默认关闭，见 D3）：开启后可选更新在 WiFi 下自动下载，
  下载完成弹一次安装确认（平台边界：无法真静默）；强制更新不受该开关影响。

C7 数据保留验证（纳入单测与真机验收）：
- 升级前后核对：JWT/邮箱登录态、配对/绑定、策略、公告、使用记录、报告缓存、KeyStore/P2P 证书、DB 可解密；
- 复核 `MY_PACKAGE_REPLACED` 处理不清理任何业务数据。

### D. Windows 家长端（本期预留）
- 不改实现；仅输出接口预留说明（version 检查接口可用、下载中心 zip 下载、安装方式建议）。

## 四、必须取消/替换的现状
- 现状：无自动更新机制；下载中心仅有静态下载页；版本号已跟随 Git tag（BuildConfig.VERSION_NAME）。
- 新增：服务端更新清单 + admin 发布推送 + 客户端检查/下载/安装闭环；关于页新增更新入口；
  下载中心由静态页升级为「更新清单驱动」。

## 五、验收标准
1. admin 发布并推送 → 在线真机（OPPO/华为）收到更新通知；离线设备联网启动后自动检查到更新。
2. 可选更新可「以后再说/跳过本版本」；强制更新（minVersionCode）不可跳过。
3. 下载进度正确、可取消；SHA-256 校验失败拒绝安装并可重试；安装成功后版本号更新。
4. 升级前后数据一致（登录态/配对/策略/公告/使用记录/报告/KeyStore/DB 均保留）——真机实测并出核对清单。
5. 家长端「关于 → 更新软件」可用，且兜底指向 xpc.winann.com。
6. 儿童端在更新流程中守护不中断；升级后守护自动恢复。
7. 回归：Web 单测、Android 单测（160+）、Windows 单测（15）、npm build、Release APK 构建；
   真机升级回归不破坏现有连线与倒计时功能。
8. 安全：仅 HTTPS；SHA-256；防降级；admin 操作有审计；检查接口限频。

## 八、行业惯例参考（调研结论）
- 强制/可选更新普遍用「最小版本阈值」判定：低于 minVersion → 强制，否则可选（Google Play In-App Updates / Flutter upgrader 等）。
- 自托管 APK 分发（非 Play 渠道）需自建：版本检查 API + ABI 匹配 + SHA-256 校验 + PackageInstaller/未知来源引导。
- 更新说明（changelog）与版本号同清单下发，客户端弹窗展示，避免用户「黑盒更新」。
- 大文件下载普遍默认 WiFi 优先、可暂停/取消、失败重试。
- 静默安装仅系统/特权应用可行；普通 App 的"自动更新"实际为「预下载 + 一次确认」，需如实向用户说明。
