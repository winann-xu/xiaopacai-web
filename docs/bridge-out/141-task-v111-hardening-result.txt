四、四项缺陷修复要点
【Bug1 上滑结束管控失效】
- 1-A 两守护服务 android:stopWithTask="false"（OPPO 真机根因）+ Manifest 回归单测
- 1-B ColorOS 保活四项引导（权限管理页专属卡片：自启动/后台冻结/电池白名单/最近任务锁定；
  系统无检测接口，如实标注「引导项」，不伪造状态）
- 1-C Device Owner 仅检测展示（不落地 DPC、无 ADB 引导），docs/DEVICE_OWNER.md
- 1-D 失守监控全链路：儿童端 GuardDownMonitor 持久化 + P2P guard_event（含健康度快照，
  离线队列 SyncManager 冲刷）→ 家长端本地落盘 + 高优通知（id 4001）+ 云端转传
  POST /api/guard-events；恢复后立即重拦截并通知家长

【Bug2 儿童端倒计时不更新】
- 每秒本地倒计时 HH:MM:SS：剩余 = 今日限额 −（最近已用 + 距最近采集的交互增量）
- 与任务书文字的差异（已在 ADR-0016-2 裁决）：增量仅屏幕交互时累计，熄屏不虚减——
  若按墙钟累计，夜间熄屏会凭空扣减额度，违背数据真实性；60s 采集锚点下增量上限 60s
- 归零立即锁定（lockIfCountdownExpired 走 TimeoutExecutor，与 60s 采集判定双保险，
  消除 ≤60s 空窗）；权限撤销/采集异常/超 3 周期未成功 → 如实显示「守护失效」不假倒计时

【Bug3 日志未上传 + Web 查日志报错】
- 3-A 根因修复：AppLogEntry 显式 ToTable("app_logs")（EF 此前按 DbSet 属性名查
  AppLogEntries 表 → "no such table" 500）；存量库零迁移；真实 SQLite 回归单测钉死
- 3-B 登录/绑定成功立即上传；失败 5/15/60 分钟指数退避（此后维持 60），6 小时周期兜底保留
- 3-C 日志页如实展示上次成功时间/失败原因/重试计划（成功自动消失）；Web 日志页补「接收时间」列

【Bug4 无障碍权限丢失】
- 4-A 事件+定时双触发：亮屏/解锁（守护前台服务动态注册）+ 应用更新
  （MY_PACKAGE_REPLACED 静态兜底）+ 回前台（Application 回调）→ 30 秒节流即时自检；
  每分钟轮询兜底保留。发现被关立即高优通知 + 一键直达无障碍设置，
  文案如实区分「管控曾生效=拦截已失效」/「未生效=守护受影响」
- 4-B 与 1-B 合并：家长端守护状态页 + Web 设备页健康度（score/100、6 项真实勾叉、
  失守历史含开始/恢复/时长），无数据如实显示「待上报」

五、真机回归清单（建议 OPPO 为主，按缺陷逐项验证）
1. Bug1：儿童端运行中上滑最近任务结束小趴菜 → 约 5 秒内守护自动恢复（通知提示），
   家长端收到「失守开始→已恢复」通知并展示失守时长；管控重新生效（超时应用可被拦截）
2. Bug2：儿童端首页倒计时逐秒走动（HH:MM:SS）；把限额调到 1 分钟观察归零瞬间
   → 立即锁定（不等下一个采集周期）；进设置撤销「使用情况访问」→ 首页显示「守护失效」而非假倒计时
3. Bug4：进系统设置关闭小趴菜无障碍 → 立即收到高优通知，点击「去开启无障碍」直达设置页；
   家长端/Web 健康度同步变为危险状态
4. Bug3：家长端登录成功 → 日志自动上传；Web「运行日志」页可查到新日志（时间+接收时间）；
   日志页显示「上次成功」时间；断开网络手动上传 → 显示失败原因与 5 分钟后重试计划
5. 健康度：家长端「守护状态」页与 Web 设备详情展示 score 与 6 项权限状态，与真机实际一致

六、边界如实说明（不夸大能力）
- 第三方应用无法自动重新开启无障碍服务（平台硬限制），只能检测+引导+告警
- 被强制停止的应用无法自恢复，打开应用即恢复
- ColorOS 保活四项为引导项（无检测接口）；Device Owner 不自动激活
- 任务书未确认项一律未实施（如屏蔽系统设置页）；未引入黑科技保活
- 桌面端/Windows 侧本轮无改动，如回归请以既有 15 项用例为准
